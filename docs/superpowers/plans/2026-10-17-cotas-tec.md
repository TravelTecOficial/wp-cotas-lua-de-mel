# Cotas Tec — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plugin WordPress "Cotas Tec": agência cadastra casais com cotas de lua de mel; convidado escolhe a cota, deixa nome/e-mail/WhatsApp/mensagem e vê os dados da conta do casal; casal recebe e-mail; presente fica gravado no painel.

**Architecture:** Plugin PHP puro no molde do Viator Tec (`includes/*.php` por responsabilidade, prefixo `ctec_`, atualização pelo GitHub). Casal = tipo de post público `ctec_casal` em `/lua-de-mel/<slug>/`, renderizado por template próprio entre `get_header()`/`get_footer()` (cabeçalho e rodapé do site intactos). Presente = tipo de post privado `ctec_presente`, criado por um endpoint REST público que devolve os dados da conta (eles nunca vão no HTML da página).

**Tech Stack:** PHP 7.4+, WordPress, JS puro (sem jQuery), testes em php-wasm (Node) como no Viator Tec, empacotamento em Python.

**Spec:** `docs/superpowers/specs/2026-10-17-cotas-tec-design.md`

## Global Constraints

- Repositório: `Clientes/_wordpress-base/padrao/plugin-cotas`, GitHub **público** `TravelTecOficial/cotas-tec` (igual ao Viator Tec, para atualizar sem token), branch `main`.
- Pasta do plugin `cotas-tec/`, arquivo principal `cotas-tec/cotas-tec.php`, constante `CTEC_VERSION`, anexo da release `cotas-tec.zip`.
- Primeira versão: **0.1.0**. Toda entrega atualiza `Version:`, `CTEC_VERSION` e `CHANGELOG.md`.
- Endereço do casal: `/lua-de-mel/<slug>/`; página com `<meta name="robots" content="noindex, nofollow">`.
- Nunca mexer em Theme Builder, menu ou páginas do site.
- Cores: `var(--e-global-color-primary, #E98300)`; títulos de seção com seletor `body h2.ctec-…` (mais forte que o Kit).
- Textos em português; moeda `R$ 1.000,00` (`number_format( $v, 2, ',', '.' )`).
- Sugestão de cotas de casal novo: Bronze 50, Prata 100, Ouro 250, Diamante 500, Safira 1000.
- "Como funciona" fixo: "Escolha uma cota ou monte seu presente" / "Deixe seu nome e uma mensagem para os noivos" / "Faça o depósito na conta do casal".
- Testes nunca em localhost do dono: o teste de verdade é no site-modelo do Voucher Tec.

## Review Focus

- Página em cache (LiteSpeed): o envio não pode depender de nonce gerado na página → endpoint público sem nonce, protegido por campo isca + limite de 10 envios/hora por IP. Teste em Task 4.
- Valor livre digitado como "1.500,00", "1500", "R$ 50" ou "abc" → converte os três primeiros, recusa o último e valores < 1. Teste em Task 4.
- Cota enviada que não existe no casal (índice adulterado) ou casal em rascunho → erro 404, nada gravado. Teste em Task 4.
- Falha do `wp_mail` (site sem SMTP) → presente gravado e dados da conta exibidos mesmo assim. Teste em Task 4.
- Textos com HTML/aspas em nomes, mensagem e dados da conta → escapados na página, no e-mail e no CSV; CSV com BOM para abrir certo no Excel. Testes em Tasks 3, 4 e 5.

### Task 4: Presentear — endpoint, gravação e e-mail

**Files:**
- Create: `cotas-tec/includes/presente.php`
- Test: `tests/php/presente.test.php`

**Interfaces:**
- Consumes: `ctec_dados_casal()`, `ctec_valor()`, `ctec_formatar_valor()`.
- Produces:
  - Rota REST `POST ctec/v1/presente`, `permission_callback => '__return_true'`, chama `ctec_processar_presente( array $dados, string $ip ): array|WP_Error`.
  - `ctec_processar_presente` — ordem: (1) isca `ctec_site` preenchida → devolve sucesso falso `['ok'=>true,'conta'=>'']` sem gravar; (2) limite: transient `ctec_ip_<md5(ip)>` > 10 → `WP_Error('ctec_limite','Muitos envios. Tente de novo mais tarde.',['status'=>429])`; (3) casal inexistente ou não `publish` → `WP_Error(...,404)`; (4) `ctec_validar_presente`; (5) `ctec_gravar_presente`; (6) `wp_mail` com `ctec_email_presente` — resultado ignorado; (7) devolve `['ok'=>true,'conta'=>$casal['conta']]`.
  - `ctec_validar_presente( array $dados, array $casal ): array|WP_Error` — exige nome, e-mail válido, WhatsApp com ≥ 10 dígitos; `cota` = índice existente em `$casal['cotas']` (usa nome e valor do cadastro, nunca do envio) ou `'livre'` (exige `presente_nome` e `ctec_valor(presente_valor) >= 1`). Devolve `['casal'=>id,'cota'=>nome,'valor'=>float,'nome','email','whatsapp','mensagem']`. Erros com `status` 400 e mensagem em português.
  - `ctec_gravar_presente( array $p ): int` — `wp_insert_post` tipo `ctec_presente`, status `private`, título `"<cota> — <nome>"`, metas `_ctec_casal`, `_ctec_cota`, `_ctec_valor`, `_ctec_nome`, `_ctec_email`, `_ctec_whatsapp`, `_ctec_mensagem`.
  - `ctec_email_presente( array $p, array $casal ): array` — `['para'=>$casal['email'],'assunto'=>'Você recebeu um presente: <cota>','corpo'=>texto puro,'cabecalhos'=>['Reply-To: <nome> <email>']]`; corpo com cota, valor formatado, nome, e-mail, WhatsApp, mensagem e "Confira o depósito na sua conta antes de agradecer." Sem e-mail do casal → não chama `wp_mail`.

- [ ] **Step 1: testes** — cota 2 de um casal com 5 cotas grava valor 250.0 mesmo se o envio mandar `valor=1`; `'livre'` com "1.500,00" grava 1500.0; `'livre'` com "abc" ou "0,50" → erro 400; índice 9 → erro 400; casal em rascunho → 404; isca preenchida → nada gravado, nada enviado; 11º envio do mesmo IP → 429; `$GLOBALS['ct_mail_ok']=false` → ainda grava e devolve a conta; e-mail tem assunto `Você recebeu um presente: Ouro`, `Reply-To` com o convidado e a mensagem dele sem tags HTML.
- [ ] **Step 2:** `node run.mjs presente` → FALHA.
- [ ] **Step 3:** Implementar.
- [ ] **Step 4:** `node run.mjs presente` → OK.
